번들링
- 여러개의 파일을 하나의 파일로 결합하는 과정
- 웹서비스는 서로다른 확장자의 여러개의 파일로 구성됨

리소스는 네트워크 요청에 의해 가져와진다
- 스크립트가 로드되어 실행되기전의 아래의 내용이 실행 못된다

번들러는 수많은 파일을 적절한 단위로 쪼개서 의존성을 해결하고
하나의 거대한 파일이나 여러개의 chunk로 제공하게 한다
- 네트워크 요청횟수가 줄어듦
- 미사용 코드를 제거해주거나 난독화를 해서 용량을 줄여주고 직접 코드가 노출되지않게

리액트는 서버가 아닌 UI 라이브러리
- JSX로 선언적으로 작성하면 js엔진에 의해 실행되어 화면을 렌더링
- SSR은 브라우저가 아닌 서버에서 JSX => HTML 문자열로 변환

SEO
- 웹페이지를 검색엔진 결과페이지에 높은 순위로 노출하기 위한 최적화
- 크롤러가 웹페이지의 구조, 링크, 사이트맵등을 수집하여 검색 우선순위를 결정
- 최적화를 하려면 크롤러가 수집하는 요소와 권장사항 고려 필요
- 리액트는 처음에 빈 HTML이라 SEO에 좋지 않음

리액트는 일관적으로 동작하는 컴포넌트를 트리구조로 구성할떄 효율적으로 동작
- 캔버스나 그래픽을 렌더링하는건 표현 및 구현이 어렵고 효과적이지 않음

-----------------------------------------------------

리액트는 UI를 위한 라이브러리
- JSX 문법을 제공하여 컴포넌트를 작성하게 함 => 브라우져에 렌더링해줌
- react-dom과 react-native로 렌더러 라이브러리는 별도로 분리되어있다
  - 생명주기와 state / 렌더링 우선순위는 리액트 라이브러리에서 구현

-----------------------------------------------------

서비스가 복잡해지고 상호작용이 많을 수록 표준 웹 API로는 구현 및 최적화가 어려움
- 상태관리가 어렵다
  - 상태를 바꾸고 화면을 업데이트를 직접해야하는데 이게 상태가많아지면...
- DOM조작을 직접해야한다

-----------------------------------------------------

리액트로 개발하면 처음에는 div하나만 있고 스크립트가 로드되고 실행되어
동적으로 화면을 렌더링한다.

-----------------------------------------------------

초기의 웹은 정적인 문서여서 html + css만 잘 작성하면 됨
현대의 웹은 상호작용이 빈번하게 발생하여 화면 업데이트 유발

리액트는 선언적 UI와 컴포넌트 기반 아키텍처를 통해 복잡한 UI 상태관리를
간단하게 했지만 무언갈 하니까 오버헤드는 발생 ㅇㅇ

성능 오버헤드를 줄이기 위해 가상 돔 도입
- 전체 렌더트리에서 일부만 업데이트
- 비슷한 시점에 발생하는 변경사항은 묶어서 배치처리

가상 돔은 메모리상 값으로 유지되는 UI를 나타내는 객체
- JSX로 작성한 리턴 값이 DOM트리와 유사한 형태로 메모리에 유지
  - type / state / props / parent / 작업 우선순위 / sideEffect...
- react-dom이 이 객체와 실제 DOM과 동기화

- 이를 통해 개발자는 DOM을 어떻게 조작해야할지 배치처리해야할지를 몰라도 됨
- 단지 상태만을 알맞게 적용되게 작성하고 JSX를 통해 요소를 선언적으로 정의

가상 DOM은 Value DOM이라고 볼수도 있음
- UI를 값으로 정의하고 메모리에 저장하여 다루는것이 핵심
- 실제 DOM이나 네이티브 요소와 다른 추상화된 계층을 가지고 동기화

-----------------------------------------------------

재조정
- 상태 변경시 먼저 새로운 가상 DOM을 생성하고 이전의 가상 DOM과 비교하여 
  실제 DOM에 반영할 항목을 계산하여 이부분만 반영하는 과정
- UI의 변경사항은 배치처리

render: 새로운 가상 DOM을 만들어 기존 가상 DOM과의 차이를 계산하는 과정
- state, props 변경시 이를 기반으로 가상 DOM을 새로 생성
- 렌더는 "중단가능"하며 다시 실행될 수 있음

commit: 변경사항만 모아 실제 DOM에 반영하는 과정
- 반영이후 생명주기 메소드 실행
- 중단되지 않고 한번에 실행

- 렌더 과정시 반영할 실제 DOM변경사항을 최소화
- 배치 처리를 통해 여러 업데이트를 한번에 반영

-----------------------------------------------------

react는 거대한 라이브러리로 구현한 대신 여러개의 라이브러리로 모듈화
- 독립적인 모듈화로 가상 DOM과 스케쥴링 알고리즘을 react-native에도 동일하게 적용 
- react는 상태 / 라이프사이클 / 가상 DOM -> DOM 동기화
- react-dom(렌더러) / react-conciler / scheduler

-----------------------------------------------------

JSX 문법으로 요소를 표현
- 바벨같은 트랜스파일러에 의해 ReactElement를 리턴하는 함수 호출로 변환됨
- 가상 DOM구조를 구축
- JSX는 문법 확장일 뿐

리액트는 자체적인 스케쥴러로 렌더링 우선순위를 결정
- 작업 단위는 렌더링 태스크
- 우선순위 큐인 태스크 큐 관리
- 렌더링이나 리렌더링이나 발생할때마다 컴포넌트와 자식 컴포넌트들의 
  렌더링 태스크 생성하고 우선순위에 맞게 태스크 큐에 인입
- 변경사항에 영향을 받는 전체 컴포넌트를 하나의 태스크로 만듦
- 연속으로 발생하는 상태변경은 하나의 태스크로 묶이게 배치 처리

스케쥴러가 주어진 시간동안 while 루프하면서 태스크 큐에 
다음 태스크가 있는지 확인하고 있다면 콜백 호출
- 우선순위 기반으로 동작하여 사용자 체감 성능을 향상
- 태스크 생성시간 + 우선순위에 의해 만료시간이 정해진다.
- 만료시간을 기준으로 큐에서 정렬된다
