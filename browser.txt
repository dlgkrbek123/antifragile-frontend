브라우져는 다양한 구성요소로 구현됨
- 렌더링 엔진
- js 엔진
- 네트워크 요청을 처리하는 엔진

다양한 기능을 수행
- 도메인 주소를 IP주소로 변환
- HTML등의 리소스 로딩
- https 커넥션을 맺게 네트워크 요청
- 로컬 스토리지 / 세션 스토리지 / 쿠키등의 저장소 관리

여러 기능을 의미있는 단위로 나누어 관리함

UI
- 브라우져 상단바 영역에 해당하는 부분
- 주소 표시줄 / 내비게이션

UI 백엔드
- OS환경에 따라 기본적인 UI 요소를 그리는 인터페이스 제공
- 드롭다운 / 다이얼로그 / 스크롤 바

브라우져 엔진
- 내부의 서로다른 요소들사이의 연결고리 역할
- 각 구성요소과 독립적으로 기능하면서도 상호작용할 수 있게 조율
- UI 주소창에 url 입력시 네트워크 인터페이스와 상호작용하여
  요청을 생성하고 응답 처리후 렌더링 엔진에 적용
- JS엔진과도 상호작용

렌더링 엔진
- 브라우저 엔진이 여러 인터페이스와 상호작용하여 가져온 페이지를 화면에 시각적으로 표현
- HTML, CSS를 해석하고 처리하여 결과를 픽셀 그래픽 형태로 렌더링

- 렌더링: 문서구조와 스타일 정보를 결합하여 표현
- 렌더링 엔진은 webkit과 gecko가 있음

네트워킹 엔진
- 네트워크 요청을 처리하는 역할
- HTML, CSS, JS, Image, font등의 리소스 요청
- 브라우져에서 요청을 보내야 할떄 요청을 보내고 응답을 처리
- 보안상의 이유로 HTTP대신 암호화 레이어가 추가된 HTTPS 권장

자바스크립트 엔진
- JS코드를 해석하고 실행하는 역할
- DOM과 CSSOM을 조작해 화면에 그려지는 요소를 조작
  - 실행 후 렌더링 엔진과 상호작용

데이터 영속성
- 쿠키 / 로컬스토리지 / 세션 스토리지/ 캐시등의 기술을 활용해 페이지와 관련된 데이터를 저장
- 쿠키 인증방식은 브라우져에 세션정보를 저장하고 매요청마다 이정보를 네트워크 요청에 포함

크롬과 크로미엄의 차이는?
- 크로미엄은 오픈소스 프로젝트
- 크로미엄자체는 기본 브라우저 기능만 제공
- 여기에 여러 기능을 추가 보완하여 크롬과 같은 브라우져가 제공됨

크롬은 크로미엄을 기반으로 한 상용버전 웹 브라우저
- 크로미엄에 추가기능 / 디자인 변경 / 보안패치등을 포함
- 즉 크로미엄은 핵심기능을 포함하는 코어고 각 브라우저는 여기에 개선사항을 적용

세부구현은 제각각이여도 브라우저가 지켜야하는 표준 인터페이스가 있음
- 국제 웹 표준단체에서 웹 표준 인터페이스를 결정

W3C: html, css, svg, 웹접근성 가이드라인등의 표준 개발
- HTML5, CSS, DOM을 표준화했음

WHATWG
- HTML, DOM, Fetch API등 웹표준의 리빙 스탠더드를 제공
- 지속해서 업데이트 되는 온라인 명세를 관리

IETF
- HTTP, TLS, WebRTC등의 프로토콜과 관련된 RFC 발행
- 도메인 네임에서 IP주소를 획득하는 DNS resolve나 보안 레이어가 추가된
  HTTPS의 같은 네트워크 명세

ECMA 인터내셔널
- ECMAScript, JSON을 표준화
- 핵심 기능남능ㄹ 정의하므로 호스트 환경에서 제공되는 기능은 정의 X

특정 브라우져는 어떤 속성을 미지원하거나 버전이 낮은경우에 폴리필이 필요할 수 있다.
- 폴리필은 브라우저간 미세한 구현차이나 미지원 기능을 보완하고자 사용하는 코드조각
  - 이전 버전 브라우저에서도 동일한 기능을 사용할 수 있도록 보완해주는 코드
  - 이미 지원하는 브라우저에서는 영향을 미치지 않게 설계
  - 좋긴한데 임시방편이기도 하다
  - 브라우저의 명세와 구현이 분리되므로 등장
- 크로스 브라우징의 피로함 ㅠㅠ
